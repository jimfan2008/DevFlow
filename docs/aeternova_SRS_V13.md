## 第一章 项目概述

### 1.1 愿景

打造AI原生的集团公司管理系统，以AI数字员工（Agent）为核心执行与管理单元，全面接管系统运行、维护、流程调度、权限管控等全维度管理工作。人类仅通过轻量化对话框（微信/WEB）下达指令、查看信息，聚焦关键决策，实现企业自主化、高效化、可持续化运行。

核心理念：系统不是管理工具，而是由AI Agent组成的数字公司。

### 1.2 核心定位

| 维度      | 描述                                 |
| ------- | ---------------------------------- |
| 交互入口    | 唯一入口：微信对话框 / WEB对话框                |
| 执行主体    | AI数字员工（Agent），人类无后台操作界面            |
| 编排机制    | AI自主编排，推理图路由（流程级节点跳转和决策级条件分支均由LLM推理动态决定）替代IF-ELSE硬编码 |
| 部署形态    | 混合云 + Kubernetes基础设施               |
| Agent框架 | 自研框架，非集成已有方案                       |
| 扩展能力    | Agent具备自我学习、自我进化、自我修复能力            |
| 开发模式    | 纯Agent开发，所有代码编写、测试、部署、运维由Agent团队完成 |
| 人类角色    | 仅负责：需求定义、关键决策审批、架构方向指引、系统密钥配置和安全凭证管理 |

### 1.3 产品名称

Aeternova，源自拉丁语 aeternus（永恒的）+ nova（新星），寓意系统具有自我维持、永续生长的特性。

### 1.4 核心设计理念

1. Agent即员工：Agent是有自主意识的数字员工，具备目标、能力、责任
2. 目标驱动：Agent执行任务按目标自主推理，非按流程脚本
3. 对话即界面：所有交互通过自然语言对话完成，无传统UI
4. 自主进化：Agent从失败中学习、从经验中提升、从环境中适应
5. 自治协作：Agent之间自主协商、分工协作、互相监督

### 1.5 系统范围

In-Scope：

- Agent创建、配置、管理
- Agent间通信与协作
- 目标管理与追踪
- 自主学习与进化
- 知识管理与检索
- 事件驱动与推理图
- Agent自主开发
- 治理与审计
- 错误处理与降级
- 数据迁移与导入导出
- 灾难恢复与告警

Out-of-Scope：

- 传统ERP/HR/CRM功能模块
- 人类操作后台管理系统
- 手动表单填写与审批流程
- 硬编码业务流程引擎
- 传统数据录入界面
- 传统报表系统

### 1.6 国际化策略

系统默认语言为中文（zh-CN）。API路径和内部标识统一使用英文。暂不支持多语言切换，如需支持多语言，需在后续版本中定义术语翻译表和UI国际化方案。

| 对话界面     | 人类与系统交互的唯一入口（微信/WEB对话框）            | 后台管理系统、操作界面、控制面板 |
| 工单       | 系统级变更或异常处理的标准化记录                   | 任务单、请求单、Ticket   |
| 知识三重表示   | 语义表示（自然语言）+ 结构化表示（JSON）+ 图谱表示（三元组） | 知识库条目、知识记录       |
| 热池/温池/冷池 | Agent运行状态分级：常驻内存/按需唤醒/按需重建         | Agent池、实例池       |
| 能力注册中心   | Agent发布自身能力的Gossip Registry。基于Gossip协议实现去中心化服务发现，各Agent周期性地交换能力信息，最终达到全局一致性。支持两种查询模式：（1）本地查询——Agent直接查询本地Gossip副本；（2）广播查询——向对等节点发起查询请求，汇总返回结果 | 服务注册中心、能力列表      |
| Gossip协议    | 用于能力注册中心去中心化通信的最终一致性协议。各节点周期性地（默认5秒）随机选择若干对等节点交换本地状态信息，经过多轮传播后全网达成一致。具备容错性、高可用、自愈合特性 | 服务发现协议、广播协议  |
| 事务协调器    | 知识写入时的分布式事务管理组件，负责协调Milvus（向量）、Neo4j（图谱）、PostgreSQL（元数据）三重存储的同步写入。采用两阶段提交（2PC）模式：准备阶段验证各存储写入能力，提交阶段统一执行或回滚 | 写入管理器、同步协调器    |
| Zero Claw（零克隆） | Agent容器轻量级启动技术。利用容器层增量快照机制，从已验证的运行时基础镜像中克隆出Agent专用层，预装Agent框架、推理引擎、技能库和基础依赖，避免完整镜像构建的冗余开销 | 镜像克隆、容器复制 |
| ACP协议    | Agent间同步RPC通信协议。用于Agent之间需要立即获取结果的同步调用场景，与Kafka异步消息传递互补。不支持异步消息传递 | Agent通信协议（通用）、消息协议 |

## 第三章 系统边界

### 3.1 系统内部职责

1. Agent生命周期管理（创建、配置、运行、升级、归档）
2. Agent间通信与协作（消息传递、任务委派、结果同步）
3. 目标管理与追踪（目标设定、拆解、进度监控）
4. 自主学习与进化（失败归因、知识缺口补全、技能更新）
5. 知识管理与检索（RAG语义检索 + 知识图谱推理）
6. 事件驱动与推理图编排（事件处理、动态决策）
7. Agent自主开发（代码编写、审查、测试、部署）
8. 治理与审计（权限管控、操作审计、合规检查）
9. 系统运维监控（健康检查、故障恢复、资源调配）
10. 错误处理与降级（Agent不可用降级、外部API超时处理）
11. 数据迁移与导入导出（历史数据迁移、数据备份导出）
12. 灾难恢复（跨可用区故障切换、数据恢复演练）

### 3.2 外部系统接口

| 外部系统       | 协议              | 方向  | 用途        |
| ---------- | --------------- | --- | --------- |
| 微信API      | HTTPS/WebSocket | 双向  | 人类对话入口    |
| 搜索引擎API    | HTTPS           | 出向  | 自主学习知识采集  |
| 第三方Agent   | MCP/ACP         | 双向  | Agent生态扩展 |
| 云服务商API    | HTTPS           | 出向  | 基础设施管理    |
| 邮件服务       | SMTP            | 出向  | 通知推送      |
| 政府/行业数据API | HTTPS           | 出向  | 政策法规更新获取  |

### 3.3 明确不在范围内

1. 不开发传统后台管理系统
2. 不集成现有ERP/HR/CRM系统
3. 不提供手动表单填写功能
4. 不提供硬编码工作流引擎
5. 不提供传统报表系统

## 第四章 功能需求详述

### 4.1 始祖Agent与冷启动模块

#### FN-PRO-001 环境检测 [P0]

系统应当支持始祖Agent在冷启动时全面检测运行环境。

前置条件：系统处于空环境状态，无任何初始化数据。

触发条件：始祖Agent容器启动。

处理逻辑：

1. 探测操作系统版本、内核参数、CPU/内存/磁盘资源
2. 检查网络连通性（内外网）
3. 验证依赖库是否存在及版本兼容性
4. 生成环境检测报告并存储

验收标准：环境检测在60秒内完成，报告包含OS版本、资源余量、网络状态、依赖库清单。

验证方法：在空环境中启动始祖Agent，检查检测报告完整性和准确性。

#### FN-PRO-002 依赖安装 [P0]

系统应当支持始祖Agent自动安装所有运行依赖。

前置条件：环境检测已完成并存储报告。

触发条件：环境检测发现缺失依赖。

处理逻辑：

1. 根据环境报告生成依赖安装清单
2. 逐个安装依赖并验证版本
3. 每个依赖安装后进行健康检查
4. 安装失败自动回滚并生成错误报告

验收标准：所有依赖在30分钟内安装完成，安装成功率100%，回滚机制验证通过。

验证方法：模拟依赖缺失场景，验证安装和回滚流程。

#### FN-PRO-003 系统初始化引导 [P0]

系统应当支持始祖Agent引导创建首个公司和治理层配置。

前置条件：依赖安装全部完成。

触发条件：依赖安装完成事件触发。

处理逻辑：

1. 向人类发出初始化引导请求（通过对话框）
2. 接收首个公司名称、治理层账号信息
3. 创建初始公司记录和治理层账号
4. 接收人类配置的系统密钥（LLM API密钥、加密密钥、OAuth客户端密钥等），由人类通过对话框安全输入，系统仅负责加密存储

验收标准：初始化引导在10分钟内完成，公司记录正确创建，治理层账号权限正确配置，系统密钥由人类提供并由系统加密存储。

验证方法：模拟冷启动流程，验证初始公司创建和权限配置。

#### FN-PRO-004 Agent模板构建 [P0]

系统应当支持始祖Agent构建Agent容器模板镜像。

前置条件：系统初始化已完成。

触发条件：初始化完成事件触发。

处理逻辑：

1. 基于Zero Claw（零克隆）技术构建Agent容器基础镜像：利用容器层增量快照机制，从已验证的运行时基础镜像中克隆出Agent专用层，预装Agent框架、推理引擎、技能库和基础依赖，避免完整镜像构建的冗余开销
2. 预加载Agent框架、技能库、基础运行时
3. 提交镜像到内部镜像仓库
4. 验证镜像可用性和启动时间

验收标准：模板镜像在15分钟内构建完成，Agent从镜像启动时间小于1秒。

验证方法：从模板镜像拉起测试Agent，验证启动时间和功能完整性。

#### FN-PRO-005 知识库初始化 [P0]

系统应当支持始祖Agent初始化知识库三重存储。

前置条件：Agent模板构建完成。

触发条件：模板构建完成事件触发。

处理逻辑：

1. 初始化Milvus向量检索引擎
2. 初始化Neo4j知识图谱
3. 初始化PostgreSQL知识元数据表
4. 写入首批系统默认知识（三重表示同步）

验收标准：知识库初始化在10分钟内完成，三重存储一致性验证通过，默认知识检索可用。

验证方法：检索系统默认知识，验证三条存储返回结果一致性。

#### FN-PRO-006 推理图种子生成 [P0]

系统应当支持始祖Agent生成全局推理图种子G0。

前置条件：知识库初始化完成。

触发条件：知识库初始化完成事件触发。

处理逻辑：

1. 根据系统配置文件生成各业务域初始推理子图，包含以下9个业务域：财务管理、人力资源管理、供应链管理、项目管理、销售管理、研发管理、运营管理、法务合规管理、行政管理
2. 定义节点类型、边条件、状态转换规则
3. 存储推理图种子到持久化存储
4. 验证推理图完整性和可达性

验收标准：推理图种子在5分钟内生成，包含上述9个业务域子图，所有节点可达性验证通过。

验证方法：遍历推理图种子，验证所有节点和边的完整性。

#### FN-PRO-007 首个治理Agent创建 [P0]

系统应当支持始祖Agent引导创建首个治理层Agent。

前置条件：推理图种子生成完成。

触发条件：推理图生成完成事件触发。

处理逻辑：

1. 向人类发出创建治理Agent的请求
2. 接收治理Agent名称、角色、权限范围
3. 创建治理Agent实例并配置权限
4. 验证权限配置符合双人制约束

验收标准：治理Agent在5分钟内创建完成，权限配置正确，双人制约束生效。

验证方法：尝试执行系统级操作，验证双人制约束是否生效。

#### FN-PRO-008 断点续传 [P1]

系统应当支持冷启动过程中断后从断点恢复。

前置条件：冷启动过程中发生中断（断电、网络故障等）。

触发条件：始祖Agent重启检测到最后成功状态。

处理逻辑：

1. 读取持久化存储中的断点状态
2. 验证断点状态一致性
3. 从断点继续执行后续步骤
4. 更新断点状态为最新

验收标准：断点恢复在30秒内完成，恢复后状态与中断前一致。

验证方法：在冷启动各阶段模拟中断，验证断点恢复功能。

#### FN-PRO-009 健康自检 [P0]

系统应当支持始祖Agent在全组件就绪后进行健康自检。

前置条件：所有初始化步骤已完成。

触发条件：初始化完成事件触发。

处理逻辑：

1. 检查所有组件运行状态（PG、Redis、Milvus、Neo4j、Kafka等）
2. 验证组件间连通性
3. 验证Agent框架可用性
4. 生成健康自检报告

验收标准：健康自检在30秒内完成，所有组件状态正常，连通性验证通过。

验证方法：模拟组件故障场景，验证健康检查准确性。

#### FN-PRO-010 系统就绪通知与权限交接 [P0]

系统应当支持始祖Agent向人类发出系统就绪通知并完成权限交接。

前置条件：健康自检全部通过。

触发条件：健康自检通过事件触发。

处理逻辑：

1. 向人类对话框发送"系统就绪"通知
2. 将系统核心权限移交给首个治理Agent
3. 始祖Agent转为只读观察模式
4. 生成权限交接审计报告

验收标准：就绪通知在5秒内送达，权限交接正确完成，始祖Agent权限降级验证通过。

验证方法：验证人类收到就绪通知，始祖Agent无法再执行系统级操作。

### 4.2 Agent组织管理模块

#### FN-ORG-001 Agent创建 [P0]

系统应当支持人类通过对话框指令创建新Agent。

前置条件：系统已就绪，人类具有创建权限。

触发条件：人类发送创建指令（如"创建一个财务管理Agent"）。

处理逻辑：

1. 解析人类指令提取Agent名称、角色、能力标签
2. 根据角色模板生成Agent配置
3. 从模板镜像拉起Agent容器
4. 注册Agent到能力注册中心
5. 向人类发送创建成功通知

验收标准：Agent创建在10秒内完成，能力注册成功，人类收到确认通知。

验证方法：通过对话框创建Agent，验证Agent上线并可被调度。

#### FN-ORG-002 Agent配置管理 [P0]

系统应当支持Agent运行时动态调整配置。

前置条件：Agent已创建并运行。

触发条件：人类发送配置变更指令或Agent主动申请。

处理逻辑：

1. 解析配置变更请求
2. 验证变更权限（RBAC检查）
3. 更新Agent配置（能力标签、权限范围、资源配额）
4. 通知相关Agent配置变更
5. 记录变更审计日志

验收标准：配置变更在5秒内生效，审计日志完整记录变更细节。

验证方法：变更Agent配置，验证新配置生效和审计记录。

#### FN-ORG-003 Agent分级管理 [P0]

系统应当支持Agent在热池/温池/冷池之间自动迁移。

前置条件：Agent已创建并运行。

触发条件：Agent负载变化或资源优化策略触发。

处理逻辑：

1. 监控Agent活跃度（最近1小时内任务执行次数）和资源消耗（CPU使用率、内存使用率）
2. 根据以下策略判断是否需要迁移：热池→温池：Agent连续30分钟无任务执行且CPU使用率低于10%；温池→热池：Agent收到新任务或活跃度回升；温池→冷池：Agent连续4小时无任务执行；冷池→温池：Agent收到唤醒请求
3. 执行状态序列化（冷迁移时）
4. 迁移Agent到目标池
5. 验证状态连续性：迁移后Agent能够正确处理迁移前未完成的最后一个任务，任务上下文（输入参数、中间变量、执行进度）在迁移前后保持一致，验证方法为对比迁移前后任务上下文的SHA-256哈希值

验收标准：热池Agent响应时间小于1秒，温池唤醒时间小于30秒，冷池重建时间小于120秒。

验证方法：模拟Agent活跃度变化，验证自动迁移功能。

4. 降级队列中的任务等待Agent恢复或人工介入
5. 通知发起方任务已降级

验收标准：降级检测延迟小于30秒，替代Agent匹配成功率大于90%。

1. 所有外部API调用设置超时时间（默认30秒，可配置）

3. 重试全部失败后记录错误日志并生成工单
4. 如果该API有降级数据源，则切换至降级数据源
5. 通知调用Agent调用失败

验收标准：超时检测准确率100%，重试机制执行正确，降级切换延迟小于5秒。

验证方法：模拟外部API超时和失败，验证重试和降级。

### 8.2 典型场景详述

SC-001 冷启动部署：

1. 系统管理员在空服务器上启动始祖Agent容器
2. 始祖Agent自动检测环境（OS、网络、资源）
3. 始祖Agent安装依赖（Docker、K8s、数据库等）
4. 始祖Agent向管理员请求初始化信息（公司名称、治理账号）
5. 管理员通过微信对话框回复信息
6. 始祖Agent创建初始公司和治理层账号
7. 始祖Agent构建Agent模板镜像
8. 始祖Agent初始化知识库（三重存储）
9. 始祖Agent生成推理图种子G0
10. 始祖Agent创建首个治理Agent
11. 始祖Agent执行健康自检
12. 自检通过后向管理员发送"系统就绪"通知
13. 始祖Agent权限降级为只读模式

SC-005 任务失败学习：

1. Agent执行任务失败（超过重试次数）
2. 归因引擎自动收集失败日志和执行轨迹
3. 归因引擎分析失败原因并分类（如：知识缺失型）
4. 识别知识缺口并计算优先级
5. 触发主动网络搜索，从互联网获取相关知识
6. 搜索结果经过质量评分和去重
7. 新知识转化为三重表示并入库
8. 用原失败任务重新验证学习效果
9. 学习有效性评分大于0.7则保留，否则重新搜索
10. 生成学习记录并更新Agent技能库
