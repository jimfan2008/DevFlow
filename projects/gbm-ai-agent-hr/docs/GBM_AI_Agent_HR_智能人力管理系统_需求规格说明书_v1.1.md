## 1. 引言

### 1.1 编写目的

本文档旨在定义 GBM AI Agent HR 智能人力管理系统的完整需求规格，作为系统设计、开发、测试和验收的依据。

### 1.2 项目范围

本系统覆盖企业人力资源管理的核心业务环节，包括：招聘管理、入职办理、培训管理、考勤管理、薪资管理、绩效考核、外务专员管理（工伤与住房公积金）、离职管理等全流程。

系统采用 AI 原生设计理念，以 AI 智能体为核心驱动，替代人工完成重复性、规则化、数据密集型的人力资源操作，实现 HR 工作的全面自动化。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| AI Agent | 具有自主决策和执行能力的 AI 智能体，可独立完成特定业务流程 |
| AI 原生系统 | 以 AI 能力为架构核心设计的软件系统，而非在现有系统上叠加 AI 功能 |
| AIOCR | 基于 AI 的光学字符识别技术，用于证件、文档信息提取 |
| 二维码签到 | 通过扫描唯一生成的二维码完成身份验证和签到确认 |
| 简历库 | 企业存储和管理候选人简历信息的数字化档案库 |
| 人事档案 | 员工从入职到离职全过程的资料集合 |
| 特种工 | 需要持有特种作业操作证的岗位人员 |
| 体系审核 | 企业内部管理体系（如 ISO 体系）的外部审核 |
| 前程无忧/中国人才热线 | 企业使用的招聘平台，标准简称 |
| 员工 | 普通岗位在职人员 |
| 职员 | 管理岗位人员（含主管、经理及以上管理层） |
| 工伤备案 | 向社保机构申报工伤事故的资料准备和提交流程 |
| 住房公积金 | 员工住房储蓄制度，需按月缴纳 |
| 考试二维码 | 唯一生成的考试身份验证二维码，有效期为考试开始时间前 30 分钟至考试结束后 1 小时，每个二维码仅限本人一次性使用，系统记录扫码时间、设备 IP，同一二维码被多次扫描时以首次扫描为准 |

### 1.4 参考标准

- GB/T 8567-2006 计算机软件文档编制规范
- IEEE 830-1998 软件需求规格说明标准

## 2. 项目概述

### 2.1 产品背景

企业当前人力资源管理存在以下痛点：

1. 简历筛选工作量大，人工筛选效率低，容易遗漏合适候选人
2. 入职流程繁琐，资料收集、证件录入、协议签署环节多，耗时长
3. 培训管理缺乏自动化工具，签到、考试评分、资料归集依赖人工操作
4. 考勤统计和薪资核算需要大量手工计算，容易出错
5. 外务专员工作（工伤处理、公积金管理）流程复杂，资料整理耗时
6. 绩效考核数据收集分散，汇总整理工作量大
7. 体系审核时，培训资料归集工作集中且繁琐

基于以上痛点，企业决定采用 AI 原生系统设计理念，构建一套 AI Agent 驱动的 HR 智能管理系统，实现人力资源全流程自动化。

### 2.2 AI 原生系统设计原则

本系统遵循以下 AI 原生设计原则：

1. **AI 驱动优先**：业务流程以 AI Agent 自动执行为默认模式，人工仅在异常处理、审批确认等关键环节介入
2. **端到端自动化**：从触发到完成，整个业务流程由 AI 串联执行，减少人工接力环节
3. **数据自学习**：系统通过积累历史数据持续优化匹配规则、评分模型和决策逻辑
4. **智能异常处理**：AI 自动识别异常情况并标记，而非要求人工逐条审核
5. **多模态交互**：支持扫码、OCR 识别、人脸比对、电子签名等多种自然交互方式
6. **归档自动化**：所有业务数据自动生成标准档案，无需人工整理归档

### 2.3 用户角色

| 角色 | 描述 | 主要职责 |
|------|------|----------|
| 系统管理员 | IT 管理人员 | 系统配置、权限管理、数据备份 |
| 人事专员 | HR 操作人员 | 监督 AI Agent 执行、处理异常、审批确认 |
| 部门主管 | 各部门负责人 | 面试结果确认、离职审批、绩效考核确认 |
| 新员工 | 即将入职员工 | 扫码登录、上传证件、签署协议、参加考试 |
| 在职员工 | 正式员工 | 培训签到、考试、绩效考核提交、查看工资条 |
| 外务专员 | 外部事务处理人员 | 工伤申报、公积金管理 |
| 体系审核员 | 内/外部审核人员 | 查看和导出培训、人事相关资料 |

### 2.4 业务目标

#### 2.4.1 核心目标

- 实现 HR 日常工作 90% 以上由 AI Agent 自动完成
- 简历筛选效率提升 10 倍以上
- 入职办理时间从 1-2 天缩短至 1-2 小时
- 薪资核算由 AI 自动完成计算，系统记录每笔薪资的核算依据和计算过程，支持人工复核
- 培训管理全流程自动化
- 外务专员事务处理效率提升 80%
- 体系审核资料准备时间从数天缩短至即时完成

#### 2.4.2 分阶段目标

**第一期（核心高频刚需流程）**：
- 招聘端：简历自动筛选、组卷、评分、证件识别、人脸采集
- 考勤薪资端：考勤统计、薪资核算、工资条生成
- 培训端：扫码签到、试卷阅卷
- 绩效端：考核表单收集汇总

**第二期（规则化事务）**：
- 入职：入职资料自动生成档案、电子协议核验
- 离职：离职表单自动生成
- 培训：教材转视频、培训计划智能整理
- 工伤：资料归集
- 公积金：补缴计算
- 纸质回执电子化

**第三期（优化增效）**：
- 简历库智能管理
- 特种工智能管理
- 体系审核资料一键归集
- 试用期资料自动汇总
- 各类证明智能填充
- 费用单据智能整理

## 3. 功能需求

### 3.1 招聘管理

#### 3.1.1 人力需求发布（第一期）

**功能描述**：

支持将招聘信息发布至前程无忧/中国人才热线等招聘平台。

**输入**：
- 岗位名称
- 岗位职责描述
- 任职要求（学历、经验、技能、年龄范围、证书要求等）
- 薪资范围
- 招聘人数
- 发布日期

**处理规则**：
1. 系统维护招聘平台账号信息和接口
2. 根据岗位模板自动生成招聘广告文案
3. 支持手动编辑招聘文案
4. 一键推送至已配置的招聘平台

**输出**：
- 招聘广告发布成功/失败状态
- 各平台发布链接

#### 3.1.2 多平台简历自动筛选与分类归档（第一期）

**功能描述**：

AI 自动抓取前程无忧/中国人才热线等平台的投递简历，按岗位要求智能匹配打分，自动筛选并分类归档。

**输入**：
- 岗位要求条件（学历、经验、技能、年龄、证书等）
- 各招聘平台待筛选简历数据

**处理规则**：

1. **简历抓取**：
   - AI Agent 定时抓取各招聘平台的新简历投递数据
   - 支持手动触发抓取
   - 自动去重，避免重复简历

2. **智能匹配评分**：
   - AI 解析岗位要求，建立匹配维度权重模型
   - 对每份简历进行多维度评分：
     - 学历匹配度（权重 20%）
     - 工作经验匹配度（权重 25%）
     - 技能匹配度（权重 20%）
     - 年龄匹配度（权重 10%）
     - 证书匹配度（权重 15%）
     - 综合匹配度（权重 10%，AI 语义分析）
   - 总分 0-100 分
   - 可配置合格分数线（默认 60 分）
   - **评分权重可配置说明**：评分权重（学历20%、经验25%等）支持在系统管理后台配置修改，修改后对新筛选的简历生效，不影响已评分的历史简历
   - **综合匹配度（AI 语义分析）评分规则**：AI 基于简历文本与岗位描述的语义相似度进行评分，0-10 分，由 NLP 模型自动输出，不人工干预

3. **自动分类**：
   - **分类优先级**：系统按"合格 > 待定 > 不合格"顺序判断，一条简历只会被归入一个类别（互斥规则）
   - 合格简历（分数 >= 合格线）：自动下载并导入简历库
   - 不合格简历（分数 < 合格线-10分）：自动标记为淘汰，保留记录
   - 待定简历（分数在 [合格线-10分, 合格线) 区间，即默认 50-59 分）：标记为待定，推送人事人工审核

4. **自动归档**：
   - 筛选完成后自动下载简历
   - 分类导入企业简历库
   - 同步打上岗位标签、匹配度标签
   - 建立简历电子档案

**输出**：
- 筛选报告（总投递数、合格数、淘汰数、待定数）
- 每份简历的匹配度评分和详细评分明细
- 简历自动归档至简历库
- 合格简历列表推送至人事

#### 3.1.3 面试试卷自动组卷与二维码生成（第一期）

**功能描述**：

根据面试/转岗/试用期考核岗位，AI 从题库自动抽取试题组卷，一对一生成唯一考试二维码。

**输入**：
- 岗位名称或类型
- 考试类型（面试/转岗/试用期考核）
- 考生信息（姓名、身份证号、应聘岗位等）
- 组卷规则（题型比例、难度分布、题目数量等）

**处理规则**：

1. **题库管理**：
   - 系统维护岗位题库，支持按岗位、题型、难度分类
   - 支持批量导入题目
   - 支持题目增删改查

2. **自动组卷**：
   - AI 根据岗位和考试类型从题库自动抽取试题
   - 遵循组卷规则保证题目分布合理
   - 避免重复题目
   - 支持不同考生生成不同试卷（题目随机抽取）

3. **二维码生成**：
   - 为每位考生生成唯一考试二维码
   - 二维码绑定考生信息与对应试卷
   - 二维码关联档案台账
   - 支持打印二维码或电子展示
   - 二维码有效期为考试开始时间前 30 分钟至考试结束后 1 小时，每个二维码仅限本人一次性使用。系统记录扫码时间、设备 IP，同一二维码被多次扫描时以首次扫描为准

**输出**：
- 生成的试卷内容
- 唯一二维码（可打印或电子展示）
- 考生-试卷-二维码关联记录

#### 3.1.4 面试答题自动评分（第一期）

**功能描述**：

客观题由 AI 实时阅卷评分，主观题由 AI 辅助标注建议答案，最终由人事专员人工评分确认，生成评分明细，自动汇总考核成绩并推送结果。

**输入**：
- 考生二维码（扫码登录）
- 考生答题数据

**处理规则**：

1. **扫码登录**：
   - 面试人员扫描个人二维码进行身份验证
   - 系统验证身份后加载对应试卷

2. **答题过程**：
   - 考生在线作答
   - 系统记录答题时间
   - 支持客观题（单选、多选、判断）自动提交
   - 主观题由考生在线填写文字答案或上传手写答案图片

3. **自动评分**：
   - 客观题由 AI 实时阅卷评分
   - 生成每道题的评分明细
   - 计算总分和各项得分
   - 主观题由 AI 辅助标注建议答案，最终由人事专员人工评分确认

4. **结果处理**：
   - 自动汇总考核成绩
   - 成绩数据自动归档
   - 同步推送结果至部门主管及人事
   - 支持部门主管在线确认最终结果

**输出**：
- 考生个人成绩单
- 评分明细（每题得分）
- 考核结果自动推送通知
- 成绩归档记录

#### 3.1.5 简历库管理

**功能描述**：

管理企业简历库，支持简历导入、检索、分类、标签化管理。

**输入**：
- 简历文件（PDF、Word（.doc/.docx）、TXT 格式）
- 岗位标签
- 匹配度标签

**处理规则**：

1. **自动导入**：
   - 筛选后的合格简历自动导入简历库
   - 支持手动批量导入简历
   - AI 自动解析简历内容，提取关键字段
   - 批量导入简历单次上限为 500 份，支持格式为 PDF、Word（.doc/.docx）、TXT，超过上限时系统提示分批导入

2. **智能管理**（第三期）：
   - AI 识别重复简历并标记
   - 简历信息更新提醒
   - 简历人才标签智能画像
   - 支持按岗位、技能、学历等条件检索

**输出**：
- 简历库列表
- 简历详情页面
- 检索结果
- 重复简历提醒

### 3.2 入职管理

#### 3.2.1 入职作业（第二期）

**功能描述**：

新员工扫码登录系统，完成实名认证、资料上传、协议签署等入职手续。

**输入**：
- 新员工二维码（唯一身份标识）
- 身份证正反面照片
- 学历证书照片
- 其他所需资料（如离职证明、体检报告等）

**处理规则**：

1. **扫码登录与实名认证**：
   - 新员工扫描入职二维码登录系统
   - 实名认证通过身份证 OCR 识别与公安部公民身份信息数据库接口进行比对验证，认证失败时提示员工检查证件信息或联系人事专员处理
   - 法务要求的实名认证环节自动完成，包括：身份信息核验（对接公安身份认证接口或第三方实名认证服务）、人脸与身份证照片一致性比对、是否存在冒用身份检测

2. **资料上传**：
   - 员工自行上传人事相关资料
   - 支持附件上传功能
   - 必填资料清单：学历证、身份证、离职证明、体检报告等
   - 支持多种格式（PDF/JPG/PNG）

3. **证件智能识别**：
   - AIOCR 识别上传的证件信息
   - 自动提取关键字段（姓名、身份证号、学历、专业等）
   - 校验信息完整性
   - 信息不完整时自动提示补充
   - 证件影像按类型分类存入档案库

4. **电子协议签署**（第二期）：
   - 所有需签写的附加协议导入系统
   - 员工在线阅读协议内容
   - 支持手工电子签名确认
   - 系统记录签名时间、IP 等信息
   - 电子签名符合《中华人民共和国电子签名法》第十三条规定的可靠电子签名要求，具备签名人身份唯一性、签名可控性、篡改可发现性

5. **人事基本资料自动生成**（第二期）：
   - 系统整合证件信息、实名认证、电子协议、基本信息
   - AI 自动拼接生成标准人事基础档案
   - "标准人事基础档案"指系统根据预设模板自动生成的档案，模板包含员工基本信息、证件信息、协议签署记录、入职时间等固定字段，模板由人事专员在系统后台定义和管理
   - 无需人工录入

6. **人事打印**：
   - 人事可以随需自行打印相关档案
   - 支持单份打印和批量打印

**输出**：
- 完整的人事基础档案
- 电子签名协议存档
- 证件影像档案
- 入职资料清单确认单

#### 3.2.2 人脸资料录入（第一期）

**功能描述**：

新员工入职时进行人脸采集，AI 完成人脸比对、编号绑定工号，自动录入人脸档案库。

**输入**：
- 新员工人脸照片（实时采集或上传）
- 员工工号
- 身份证信息

**处理规则**：

1. **人脸采集**：
   - 支持摄像头实时采集
   - 支持上传人脸照片
   - 系统自动检测照片质量

2. **人脸比对**：
   - AI 自动比对人脸照片与身份证照片
   - 验证身份一致性
   - 比对结果记录存档

3. **自动建档**：
   - 人脸编号自动绑定员工工号
   - 自动录入人脸档案库
   - 同步关联人事信息

**输出**：
- 人脸档案记录
- 人脸比对结果
- 绑定关系记录

#### 3.2.3 入职员工心得报告（第一期）

**功能描述**：

新员工入职后撰写心得报告，系统自动收集归档。

**输入**：
- 员工信息
- 心得报告内容（在线填写或上传）

| 操作 | 响应时间要求 |
|------|-------------|

| 二维码生成 | < 1 秒 |
| AIOCR 识别 | 单张证件 < 3 秒 |

#### 4.1.2 并发能力

- 支持至少 100 人同时在线使用
- 支持签到并发：培训签到高峰期支持至少 200 人在 10 分钟内完成扫码签到（并发签到请求不低于 30 次/秒）
- 薪资核算支持高并发数据处理

#### 4.1.3 数据处理能力

- 简历库支持存储至少 10 万份简历
- 支持日均处理 500 份简历筛选
- 支持月度全员薪资自动核算

### 4.2 安全性需求

#### 4.2.1 数据安全

- 员工个人信息（身份证、人脸等）加密存储
- 薪资数据严格权限控制
- 数据传输采用 HTTPS 加密
- 数据库自动备份（详见 6.4 数据备份策略）
- 敏感操作记录审计日志

#### 4.2.2 身份认证

- 所有用户登录需身份认证
- 面试官扫码验证登录
- 新员工实名认证
- 支持多因素认证（短信验证码）

#### 4.2.3 权限管理

- 基于角色的权限控制（RBAC）
- 不同角色访问不同功能模块
- 数据行级权限控制
- **行级权限示例**：部门主管只能查看和修改本部门员工的薪资数据和考勤记录；人事专员可以查看全公司数据但只能修改自己负责部门的数据；系统管理员拥有全部数据操作权限
- 操作权限分级管理

#### 4.2.4 日志管理和数据脱敏

- **日志管理要求**：
  - 操作日志：记录所有用户的增删改操作，包括操作人、操作时间、操作对象、操作内容、操作结果，操作日志保留期限不少于 3 年，支持按时间、用户、操作类型查询
  - 系统日志：记录系统运行状态、错误信息、异常事件，系统日志保留期限不少于 6 个月，支持按时间、日志级别查询
  - 审计日志：记录敏感数据访问、权限变更等安全相关操作，审计日志保留期限不少于 5 年，支持按时间、用户、数据类型查询

- **数据脱敏要求**：
  - 身份证号展示脱敏：显示前 3 位和后 4 位，中间以星号替换，例：110***********1234
  - 手机号展示脱敏：显示前 3 位和后 4 位，中间以星号替换，例：138****1234
  - 姓名展示脱敏：显示姓氏，名以星号替换，例：张**
  - 薪资数据仅限授权角色查看，其他角色查看时显示为"已脱敏"
  - 数据脱敏规则可在系统后台配置调整

### 4.3 可用性需求

#### 4.3.1 系统可用性

- 系统正常运行时间 >= 99.5%
- 计划维护窗口不超过每月 4 小时

#### 4.3.2 易用性

- 界面简洁直观，操作简便
- 扫码签到等关键操作流程不超过 3 步
- 支持移动端和 PC 端访问；移动端访问方式为 H5 响应式页面，通过手机浏览器访问，不支持原生 APP 和微信小程序
- 提供操作指引和帮助文档

### 4.4 可靠性需求

- 数据不丢失，关键操作有确认机制
- 系统异常时自动恢复
- 重要数据多重备份
- 薪资核算等关键操作支持校验和复核
- 灾难恢复指标：RTO（恢复时间目标）<= 4 小时，RPO（恢复点目标）<= 1 小时，即在系统故障后 4 小时内恢复服务，数据丢失不超过最近 1 小时
- **错误处理策略**：
  - 网络中断：客户端操作支持离线缓存，网络恢复后自动同步；服务端接口调用支持自动重试（最多 3 次，间隔递增），超过重试次数后提示用户稍后重试
  - 数据丢失：关键业务操作执行前自动创建数据快照，操作失败时回滚至快照状态；数据操作采用事务机制，确保数据一致性
  - AI 服务不可用：当 AI 服务不可用时，系统自动降级至人工处理模式，相关功能切换为手动操作界面，记录待 AI 恢复后批量处理的任务队列

### 4.5 可维护性需求

- 模块化设计，便于功能扩展
- 配置化规则管理（薪资规则、考勤规则等）
- 日志记录完整，便于问题排查
- 支持系统参数在线配置
- **国际化说明**：当前版本仅支持中文界面；如需要英文界面支持，需另行开发多语言适配模块

### 4.6 可扩展性需求

- 支持招聘平台接口扩展
- 支持打卡设备接口扩展
- 支持外部系统对接（如 ERP、财务系统）
- **自定义表单和流程范围定义**：自定义表单支持字段类型包括文本、数字、日期、下拉选择、附件上传；自定义流程支持节点数量不超过 10 个，支持条件分支和并行审批
- 支持 AI 模型升级和替换

### 4.7 部署环境需求

#### 4.7.1 操作系统要求

- 服务器操作系统：Linux（CentOS 7+ / Ubuntu 18.04+ / Debian 10+）或 Windows Server 2016+
- 推荐操作系统：CentOS 7.9+ 或 Ubuntu 20.04 LTS

#### 4.7.2 硬件配置最低要求

- CPU：最低 8 核，推荐 16 核及以上
- 内存：最低 32 GB，推荐 64 GB 及以上
- 存储：最低 500 GB SSD，推荐 1 TB SSD 及以上（含简历文件、证件影像等文档存储）
- AI 推理服务器（如独立部署）：GPU 最低 1 块（NVIDIA T4 及以上），推荐 2 块（NVIDIA A10 及以上）

#### 4.7.3 网络架构

- 内外网隔离：应用服务器部署在内网区域，通过反向代理对外提供 HTTPS 服务
- 防火墙策略：仅开放必要端口（HTTP 80、HTTPS 443、SSH 22），数据库端口不对外网开放
- 网络带宽：最低 100 Mbps，推荐 1 Gbps 及以上

### 4.8 系统监控与告警需求

#### 4.8.1 服务健康检查

- 系统提供健康检查接口（/health），返回各微服务/模块运行状态
- 监控项包括：CPU 使用率、内存使用率、磁盘使用率、数据库连接池状态、消息队列堆积情况
- 阈值告警：CPU > 85% 持续 5 分钟、内存 > 90%、磁盘 > 85%、数据库连接池使用率 > 80%、消息队列积压超过 1000 条
- 告警通知方式：支持短信和邮件通知，告警推送至系统管理员配置的通知联系人

#### 4.8.2 AI 模型异常检测

- 监控 AI 模型推理请求的响应时间、错误率
- 当 AI 模型错误率超过 5% 或响应时间超过 10 秒时触发告警
- 记录每次 AI 调用的模型版本、输入摘要、输出结果、耗时

#### 4.8.3 队列堆积告警

- 实时监控消息队列中待处理消息数量
- 当队列积压超过阈值（默认 500 条）时发出预警，超过 2000 条时发出严重告警
- 告警通知推送至系统管理员

### 4.9 AI 模型版本管理与回滚策略

- 系统维护 AI 模型版本 registry，记录每个模型的版本号、用途、上线时间、性能指标
- 支持多版本模型并存，新模型上线前可在测试环境验证
- 模型回滚策略：当新模型上线后出现异常（错误率 > 10% 或用户反馈异常），支持在 5 分钟内回滚至上一稳定版本
- 模型版本切换不影响正在处理的请求，新请求自动路由至目标版本

### 4.10 系统上线前数据验证与灰度发布

#### 4.10.1 数据验证

- 系统上线前执行数据验证：对比新旧系统数据一致性，验证范围包括员工档案完整率（要求 100%）、薪资数据核算结果比对（允许误差 0 元）、考勤记录条数核对（要求 100% 匹配）
- 数据验证报告由系统自动生成，包含验证通过项和差异项

#### 4.10.2 灰度发布

- 系统上线采用灰度发布策略：第一阶段对 10% 的用户/部门开放，观察 1 周；第二阶段扩大到 50%，观察 1 周；第三阶段全量上线
- 灰度期间支持一键回退至原系统
- 灰度发布期间实时监控用户反馈和系统指标

### 4.11 数据迁移需求

- 若从现有 HR 系统迁移数据，系统需提供数据迁移工具
- 支持的数据类型：员工档案、岗位信息、薪资历史、考勤记录、培训记录、绩效数据
- 迁移流程：（1）数据导出：从源系统导出结构化数据（CSV/Excel 格式）；（2）数据清洗：系统自动校验数据格式、去重、补全必填字段；（3）数据导入：批量导入至新系统；（4）数据验证：导入后执行数据一致性校验
- 迁移日志：记录每条数据的迁移状态（成功/失败/跳过），失败数据生成异常报告供人工处理
- 迁移回滚：迁移过程中支持中断和回滚，确保源系统数据不被破坏

### 6.3 数据归档策略

所有数据类型以"法律规定最低保存期限"为准，当法律规定低于 5 年时按法律规定执行，当法律规定高于 5 年时按法律规定执行，离职员工数据最低保留期限为 5 年或法律规定期限，以较长者为准。

| 数据类型 | 在线存储时间 | 归档策略 | 法律依据 |
|---------|-----------|---------|---------|
| 在职员工数据 | 永久在线 | 离职后保留 5 年或法律规定期限，以较长者为准 | 《劳动合同法》第五十条 |
| 简历数据 | 3 年在线 | 3 年后归档 | 《个人信息保护法》第十九条 |
| 考勤数据 | 2 年在线 | 2 年后归档 | 《工资支付暂行规定》第六条 |
| 薪资数据 | 永久在线 | 至少保存 2 年或法律规定期限，以较长者为准 | 《会计档案管理办法》第十六条 |
| 培训记录 | 3 年在线 | 3 年后归档 | 《劳动合同法》相关规定 |
| 绩效数据 | 2 年在线 | 2 年后归档 | 企业内部管理要求 |
| 工伤记录 | 永久在线 | 永久保存 | 《工伤保险条例》第十七条 |
| 协议文件 | 永久在线 | 劳动合同终止后至少保存 2 年或法律规定期限，以较长者为准 | 《劳动合同法》第五十条、《电子签名法》第六条 |

### 6.4 数据备份策略

- 全量备份：每周一次
- 增量备份：每天一次
- 备份保留：最近 6 个月
- 备份存储：异地存储
- 恢复演练：每季度一次

### 6.5 数据迁移策略

- **历史员工数据迁移**：支持从现有 HR 系统导出历史员工数据（Excel/CSV 格式批量导入），提供数据迁移工具进行格式校验、字段映射和数据清洗，支持断点续传，确保大批量数据迁移的完整性
- **简历数据迁移**：支持批量导入历史简历数据（Excel/CSV 格式），系统自动解析简历信息并关联到对应候选人档案，支持分批迁移和断点续传
- **迁移工具**：系统提供数据迁移工具，支持数据格式校验、字段映射配置、批量导入执行、迁移进度监控和异常数据报告生成
- **迁移验证**：迁移完成后自动执行数据一致性校验，生成迁移报告（包括成功条数、失败条数、异常数据清单），由系统管理员确认后完成迁移

## 附录 A：AI 原生系统架构设计要点

### A.1 AI Agent 编排

本系统采用多 AI Agent 协作架构：

1. **招聘 Agent**：负责简历抓取、筛选、匹配、评分全流程
2. **入职 Agent**：负责入职资料收集、证件识别、档案生成
3. **培训 Agent**：负责培训签到、考试评分、资料归集
4. **考勤 Agent**：负责考勤统计、异常识别
5. **薪资 Agent**：负责薪资核算、工资条生成
6. **绩效 Agent**：负责绩效考核数据收集和汇总
7. **外务 Agent**：负责工伤处理、公积金管理等外部事务

各 Agent 之间通过消息队列或事件总线通信（详见 5.2.5 Agent 间通信接口），实现端到端业务流程自动化。

### B.5 上线切换方案

- **灰度发布**：第一阶段对 10% 的用户/部门开放，观察 1 周；第二阶段扩大到 50%，观察 1 周；第三阶段全量上线
- **数据迁移验证**：上线前执行数据迁移，迁移完成后进行数据一致性校验（员工档案完整率 100%、薪资核算结果零误差、考勤记录 100% 匹配），校验通过后方可正式上线
- **回滚方案**：灰度发布期间如发现严重问题，支持一键回退至原系统；数据迁移过程中支持中断和回滚，确保源系统数据不被破坏
- **上线后监控**：上线后 1 周内重点监控系统运行状态、用户反馈和业务流程执行情况，由系统管理员和人事专员共同值守
