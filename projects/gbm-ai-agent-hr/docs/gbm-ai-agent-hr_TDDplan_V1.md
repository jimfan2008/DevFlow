## 4. 验收标准量化规范

| 模糊表述 | 量化标准 |
|---------|---------|
| "快速" | 响应时间 ≤ SRS §4.1.1 定义的阈值 |
| "准确" | 与手工核算结果完全吻合，或偏差在 SRS §10.2.1 定义范围内 |
| "加密存储" | AES-256 算法，密钥单独保管，DB 中不可见明文 |
| "可追溯" | 审计日志包含 SRS §4.2.1 定义的 10 个字段 |
| "高可用" | 全年正常运行时间 ≥ 99.5% |
| "实时" | 根据具体操作，在 SRS §4.1.1 定义的响应时间内完成 |
| "自动" | 无需人工干预，Agent 从触发到完成全自主闭环 |

## 6. 测试用例详表

### 6.1 M01: 招聘管理 (28 用例)

#### TC-M01-001: 人力需求解析与职位描述生成 [P1][UT]
- **描述**: 招聘 Agent 根据用人需求概要生成专业职位描述
- **输入**: 岗位名称="Java工程师"、职级="中级"、编制人数=3、到岗时限="1个月"
- **验收**: 生成的 JD 包含岗位名称、职责描述、任职要求；输出格式为结构化文本
- **前置**: 无
- **SRS**: §3.1.1

#### TC-M01-002: 多平台招聘信息自动发布 [P1][IT]
- **描述**: 招聘 Agent 自动分发 JD 至已配置的招聘平台
- **输入**: 已生成的 JD + 已配置的平台列表（前程无忧、中国人才热线）
- **验收**: 各平台返回发布成功状态码；Agent 记录各平台发布 URL 和时间戳
- **前置**: TC-M01-001
- **SRS**: §3.1.1

#### TC-M01-003: 投递量监控与自动建议 [P2][UT]
- **描述**: 发布后 Agent 持续监控投递量并自动建议文案调整
- **输入**: 已发布的招聘信息 + 投递量数据
- **验收**: 投递量低于阈值时 Agent 输出调整建议文本；建议内容基于岗位特征
- **前置**: TC-M01-002
- **SRS**: §3.1.1

#### TC-M01-004: 简历定时抓取（15 分钟间隔） [P0][IT]
- **描述**: 简历抓取 Agent 每 15 分钟从各平台拉取投递数据
- **输入**: 配置的招聘平台 API + 定时任务配置
- **验收**: 每 15 分钟执行一次拉取；成功拉取返回简历列表；拉取失败记录错误日志
- **前置**: TC-M01-002
- **SRS**: §3.1.2

#### TC-M01-005: 简历去重（姓名+身份证+岗位组合） [P0][UT]
- **描述**: 基于姓名+身份证/手机号+应聘岗位组合判重
- **输入**: 两份简历，姓名和岗位相同、身份证号相同
- **验收**: 第二份简历被标记为重复；不进入评分流程；保留原始记录
- **前置**: TC-M01-004
- **SRS**: §3.1.2

#### TC-M01-006: 身份证号格式校验 [P0][UT]
- **描述**: 验证 18 位身份证号符合 GB 11643-1999 标准
- **输入**: 有效身份证号 vs 无效身份证号（17 位/校验位错误/含字母非 X）
- **验收**: 有效号码通过校验；无效号码标记为"格式异常"；18 位最后一位可为 X/x
- **前置**: 无
- **SRS**: §3.1.2 输入校验规则

#### TC-M01-007: 手机号格式校验 [P1][UT]
- **描述**: 验证 11 位中国大陆手机号码格式
- **输入**: 有效手机号（1 开头，第二位 3-9）vs 无效手机号
- **验收**: 有效号码通过；无效号码标记为"格式异常"
- **前置**: 无
- **SRS**: §3.1.2 输入校验规则

#### TC-M01-008: 格式异常简历单独列出 [P1][UT]
- **描述**: 身份证号或手机号格式异常的简历不进入评分流程
- **输入**: 包含格式异常字段的简历
- **验收**: 该简历被单独列出；不进入自动评分；供人事专员确认处理
- **前置**: TC-M01-006, TC-M01-007
- **SRS**: §3.1.2

#### TC-M01-009: 学历匹配度评分 [P1][UT]
- **描述**: 按学历等级映射计算匹配度（博士 6/硕士 5/本科 4/大专 3/高中 2/初中 1）
- **输入**: 岗位要求本科，候选人简历分别为博士/本科/大专/高中
- **验收**: 博士=100%、本科=100%、大专=60%、高中=0%；计算公式符合 SRS 权重定义
- **前置**: 无
- **SRS**: §3.1.2 维度评分规则

#### TC-M01-010: 工作经验匹配度评分 [P1][UT]
- **描述**: 年限满足要求得满分，未满按比例计，超出设封顶系数 1.0
- **输入**: 岗位要求 5 年，候选人分别为 3/5/8 年
- **验收**: 3 年=60%、5 年=100%、8 年=100%（封顶 1.0）；权重占比 25%
- **前置**: 无
- **SRS**: §3.1.2 维度评分规则

#### TC-M01-011: 技能匹配度评分 [P1][UT]
- **描述**: 按技能关键词命中计算匹配度，支持同义词/近义模糊匹配
- **输入**: 岗位要求 5 个技能，简历命中 3 个（含 1 个同义词）
- **验收**: 命中数 4/5=80%；权重占比 20%；LLM 同义词判定结果可追溯
- **前置**: 无
- **SRS**: §3.1.2 维度评分规则

#### TC-M01-012: 年龄匹配度评分 [P2][UT]
- **描述**: 在规定区间内得满分，区间外得 0 分
- **输入**: 要求"25-35 岁"，候选人分别为 24/25/30/35/36 岁
- **验收**: 24 岁=0 分、25 岁=满分、30 岁=满分、35 岁=满分、36 岁=0 分；权重占比 5%
- **前置**: 无
- **SRS**: §3.1.2 维度评分规则

#### TC-M01-013: 证书匹配度评分 [P1][UT]
- **描述**: 持有所需证书得满分，缺失得 0 分
- **输入**: 要求特种作业证，候选人持证 vs 不持证
- **验收**: 持证=满分、不持证=0 分；权重占比 15%
- **前置**: 无
- **SRS**: §3.1.2 维度评分规则

#### TC-M01-014: 语义综合匹配度评分 [P1][UT]
- **描述**: LLM 对简历全文与 JD 进行语义比对，输出 0-100 分
- **输入**: 简历 + JD 各一份
- **验收**: 输出分数在 [0,100] 范围内；权重占比 20%
- **前置**: 无
- **SRS**: §3.1.2 维度评分规则

#### TC-M01-015: 语义评分重复性验证（偏差 ≤ ±3 分） [P0][IT]
- **描述**: 同一份简历重复评分 3 次，3 次结果偏差不超过 ±3 分
- **输入**: 同一份简历 + JD，执行 3 次独立评分
- **验收**: 3 次评分最大差值 ≤ 6 分；每季度随机抽取 50 份验证
- **前置**: TC-M01-014
- **SRS**: §3.1.2 语义综合匹配度

#### TC-M01-016: 综合得分加权求和 [P1][UT]
- **描述**: 各维度加权求和得出 0-100 综合得分
- **输入**: 6 个维度的分项得分
- **验收**: 综合得分 = 学历×15% + 经验×25% + 技能×20% + 年龄×5% + 证书×15% + 语义×20%；结果在 [0,100] 范围内
- **前置**: TC-M01-009 ~ TC-M01-014
- **SRS**: §3.1.2

#### TC-M01-017: 高潜简历自动分拣 [P1][UT]
- **描述**: 得分 > 合格线+10 分的简历自动标记为"强烈推荐"
- **输入**: 合格线=60 分，候选人得分 75 分
- **验收**: 简历被自动下载、解析、入库并标记"强烈推荐"；无需人工干预
- **前置**: TC-M01-016
- **SRS**: §3.1.2 分拣阈值

#### TC-M01-018: 候选简历提交人工审核 [P1][UT]
- **描述**: 合格线-10 ≤ 得分 ≤ 合格线+10 的简历提交人事专员审核
- **输入**: 合格线=60 分，候选人得分 65 分
- **验收**: 简历自动入库并标记"待审核"；推送至人事专员待办列表
- **前置**: TC-M01-016
- **SRS**: §3.1.2 分拣阈值

#### TC-M01-019: 淘汰简历自动标记 [P2][UT]
- **描述**: 得分 < 合格线-10 分的简历自动打淘汰标签
- **输入**: 合格线=60 分，候选人得分 40 分
- **验收**: 简历自动打淘汰标签；保留完整记录；可追溯查询
- **前置**: TC-M01-016
- **SRS**: §3.1.2 分拣阈值

#### TC-M01-020: 合格线动态调整 [P2][UT]
- **描述**: 人事专员可按岗位特性动态调整合格线阈值
- **输入**: 将某岗位合格线从 60 改为 70
- **验收**: 新合格线立即生效；后续简历按新阈值分拣；历史记录保持原有阈值
- **前置**: 无
- **SRS**: §3.1.2

#### TC-M01-021: 面试转化率回溯评估 [P0][IT]
- **描述**: 每季度评估筛选准确性，转化率低于基线 80% 时触发模型优化
- **输入**: 某岗位历史基线=30%，当季实际转化率=20%
- **验收**: 20%/30%=66.7% < 80%，触发 Agent 评分模型权重自检和优化
- **前置**: 无
- **SRS**: §3.1.2

#### TC-M01-022: 面试转化率基线更新 [P1][IT]
- **描述**: 系统运行满一个季度后，以该季度实际转化率更新基线
- **输入**: 首季度实际转化率 35%
- **验收**: 下一季度基线更新为 35%；无历史数据时初始基线为行业基准值 30%
- **前置**: TC-M01-021
- **SRS**: §3.1.2

#### TC-M01-023: 智能组卷（30-50 题/卷） [P1][UT]
- **描述**: 组卷 Agent 按规则自动出题，默认 40 题
- **输入**: 岗位类型="安全管理人员"、考试科目="安全规范"
- **验收**: 生成 40 题试卷；题型比例：单选 40%±5%、多选 30%±5%、判断 30%±5%；难度分布符合 SRS 定义
- **前置**: 无
- **SRS**: §3.1.3

#### TC-M01-024: 同岗位试卷重合度 ≤ 30% [P1][UT]
- **描述**: 同岗位同时段任意两份试卷重合题目不超过 30%
- **输入**: 同岗位生成 2 份试卷，各 40 题
- **验收**: 重合题目数 ≤ 12 题（40×30%）
- **前置**: TC-M01-023
- **SRS**: §3.1.3

#### TC-M01-025: 考试二维码生成与绑定 [P1][UT]
- **描述**: Agent 生成唯一考试二维码并与考生信息绑定
- **输入**: 考生名单（10 人）
- **验收**: 每人生成唯一二维码；扫描后正确识别考生身份；二维码不可重复使用
- **前置**: TC-M01-023
- **SRS**: §3.1.3

#### TC-M01-026: 客观题自动阅卷 [P0][UT]
- **描述**: Agent 按标准答案自动批阅客观题
- **输入**: 考生答卷（含单选、多选、判断题）
- **验收**: 单选题答对得满分/答错 0 分；多选题全对满分/部分正确 50%/有错 0 分/未作答 0 分；判断题答对满分/答错 0 分
- **前置**: 无
- **SRS**: §3.1.4

#### TC-M01-027: 主观题 AI 交叉评分 [P0][IT]
- **描述**: 两个独立 LLM 分别评分，偏差 ≤ 10 分取平均，> 10 分标记人工复核
- **输入**: 主观题答卷一份，两个 LLM 分别给出 75 分和 80 分
- **验收**: 偏差=5 ≤ 10，取平均分 77.5 分；若偏差 > 10 则标记为需人工复核
- **前置**: 无
- **SRS**: §3.1.4

#### TC-M01-028: 简历库多维标签检索 [P2][E2E]
- **描述**: 以自然语言查询简历库中的候选人
- **输入**: 自然语言 "找出所有有 5 年以上 Java 经验且做过微服务架构设计的候选人"
- **验收**: 返回匹配的候选人列表；结果按相关性排序；支持多维标签组合查询
- **前置**: 无
- **SRS**: §3.1.5

### 6.2 M02: 入职管理 (20 用例)

#### TC-M02-001: 新员工扫码登录入职门户 [P1][E2E]
- **描述**: 新员工通过扫码进入入职门户
- **输入**: 新员工手机扫描系统生成的入职二维码
- **验收**: 扫码后正确跳转到入职引导页面；页面显示待上传材料清单
- **前置**: 无
- **SRS**: §3.2.1

#### TC-M02-002: 入职材料逐项引导上传 [P1][UT]
- **描述**: Agent 引导新员工按清单逐项上传必备材料
- **输入**: 材料清单（证件照、学历证书、身份证正反面等）
- **验收**: 页面按清单顺序展示待上传项；每项上传后标记完成状态；全部上传后展示完成报告
- **前置**: TC-M02-001
- **SRS**: §3.2.1

#### TC-M02-003: 证件 OCR 识别与结构化提取 [P0][IT]
- **描述**: Agent 对上传的每个证件执行 OCR 识别
- **输入**: 身份证正面照片
- **验收**: 提取姓名、身份证号、地址、出生日期等字段；识别准确率 ≥ 98%（SRS §10.2.1）
- **前置**: 无
- **SRS**: §3.2.1, §10.2.1

#### TC-M02-004: 信息完整性校验与补传提醒 [P1][UT]
- **描述**: 识别到关键字段缺失时主动提醒新员工补传
- **输入**: 上传的身份证 OCR 结果中缺少出生日期
- **验收**: 系统提示"缺少出生日期信息"；引导重新拍摄或补传；未补传前不进入下一步
- **前置**: TC-M02-003
- **SRS**: §3.2.1

#### TC-M02-005: OCR 信息 vs 身份证原件比对 [P0][UT]
- **描述**: 自动进行实名认证比对
- **输入**: OCR 提取的身份证号 vs 员工手动输入的身份证号
- **验收**: 一致时通过认证；不一致时提示员工确认；多次不一致时标记为异常
- **前置**: TC-M02-003
- **SRS**: §3.2.1

#### TC-M02-006: 电子协议推送与手写签名 [P1][IT]
- **描述**: Agent 推送需签署的电子协议，支持手机端手写签名
- **输入**: 入职协议模板
- **验收**: 协议正确推送到新员工移动端；支持手写签名；签名后生成带时间戳和水印的 PDF
- **前置**: 无
