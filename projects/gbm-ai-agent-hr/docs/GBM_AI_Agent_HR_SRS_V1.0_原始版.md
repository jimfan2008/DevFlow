## 1. 引言

### 1.1 编写目的

本文档旨在定义 GBM AI Agent HR 智能人力管理系统的完整需求规格，作为系统设计、开发、测试和验收的依据。

### 1.2 项目范围

本系统覆盖企业人力资源管理的核心业务环节，包括：招聘管理、入职办理、培训管理、考勤管理、薪资管理、绩效考核、外务专员管理（工伤与住房公积金）、离职管理等全流程。

系统采用 AI 原生设计理念，以 AI 智能体为核心驱动，替代人工完成重复性、规则化、数据密集型的人力资源操作，实现 HR 工作的全面自动化。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| AI Agent | 具有自主决策和执行能力的 AI 智能体，可独立完成特定业务流程 |
| AI 原生系统 | 以 AI 能力为架构核心设计的软件系统，而非在现有系统上叠加 AI 功能 |
| AIOCR | 基于 AI 的光学字符识别技术，用于证件、文档信息提取 |
| 二维码签到 | 通过扫描唯一生成的二维码完成身份验证和签到确认 |
| 简历库 | 企业存储和管理候选人简历信息的数字化档案库 |
| 人事档案 | 员工从入职到离职全过程的资料集合 |
| 特种工 | 需要持有特种作业操作证的岗位人员 |
| 体系审核 | 企业内部管理体系（如 ISO 体系）的外部审核 |
| 前程无忧/中国人才热线 | 企业使用的招聘平台，标准简称 |
| 员工 | 普通岗位在职人员 |
| 职员 | 管理岗位人员（含主管、经理及以上管理层） |
| 工伤备案 | 向社保机构申报工伤事故的资料准备和提交流程 |
| 住房公积金 | 员工住房储蓄制度，需按月缴纳 |

### 1.4 参考标准

- GB/T 8567-2006 计算机软件文档编制规范
- IEEE 830-1998 软件需求规格说明标准

## 2. 项目概述

### 2.1 产品背景

企业当前人力资源管理存在以下痛点：

1. 简历筛选工作量大，人工筛选效率低，容易遗漏合适候选人
2. 入职流程繁琐，资料收集、证件录入、协议签署环节多，耗时长
3. 培训管理缺乏自动化工具，签到、考试评分、资料归集依赖人工操作
4. 考勤统计和薪资核算需要大量手工计算，容易出错
5. 外务专员工作（工伤处理、公积金管理）流程复杂，资料整理耗时
6. 绩效考核数据收集分散，汇总整理工作量大
7. 体系审核时，培训资料归集工作集中且繁琐

基于以上痛点，企业决定采用 AI 原生系统设计理念，构建一套 AI Agent 驱动的 HR 智能管理系统，实现人力资源全流程自动化。

### 2.2 AI 原生系统设计原则

本系统遵循以下 AI 原生设计原则：

1. **AI 驱动优先**：业务流程以 AI Agent 自动执行为默认模式，人工仅在以下关键环节介入：离职审批、薪资核算异常复核、工伤理赔最终确认、待定简历人工审核、主观题评分。上岗证生成、简历筛选评分、考勤统计等属于全自动化环节，不需人工审核。
2. **端到端自动化**：从触发到完成，整个业务流程由 AI 串联执行，减少人工接力环节
3. **数据自学习**：系统通过积累历史数据持续优化匹配规则、评分模型和决策逻辑
4. **智能异常处理**：AI 自动识别以下异常情况并标记：(a)薪资核算结果与上月波动超过±20%；(b)考勤异常集中爆发；(c)证书即将到期等，而非要求人工逐条审核
5. **多模态交互**：支持扫码、OCR 识别、人脸比对、电子签名等多种自然交互方式
6. **归档自动化**：所有业务数据自动生成标准档案，无需人工整理归档

### 2.3 用户角色

| 角色 | 描述 | 主要职责 |
|------|------|----------|
| 系统管理员 | IT 管理人员 | 系统配置、权限管理、数据备份 |
| 人事专员 | HR 操作人员 | 监督 AI Agent 执行、处理异常、审批确认 |
| 部门主管 | 各部门负责人 | 面试结果确认、离职审批、绩效考核确认 |
| 新员工 | 即将入职员工 | 扫码登录、上传证件、签署协议、参加考试 |
| 在职员工 | 正式员工 | 培训签到、考试、绩效考核提交、查看工资条 |
| 外务专员 | 外部事务处理人员 | 工伤申报、公积金管理 |
| 体系审核员 | 内/外部审核人员 | 查看和导出培训、人事相关资料 |

### 2.4 业务目标

#### 2.4.1 核心目标

- 实现 HR 日常工作 90% 以上由 AI Agent 自动完成
- 简历筛选效率提升 10 倍以上
- 入职办理时间从 1-2 天缩短至 1-2 小时
- 薪资核算实现全自动，零人工计算
- 培训管理全流程自动化
- 外务专员事务处理效率提升 80%
- 体系审核资料准备时间从数天缩短至即时完成

#### 2.4.2 分阶段目标

**第一期（核心高频刚需流程）**：
- 招聘端：简历自动筛选、组卷、评分、证件识别、人脸采集
- 考勤薪资端：考勤统计、薪资核算、工资条生成
- 培训端：扫码签到、试卷阅卷
- 绩效端：考核表单收集汇总

**第二期（规则化事务）**：
- 入职：入职资料自动生成档案、电子协议核验
- 离职：离职表单自动生成
- 培训：教材转视频、培训计划智能整理
- 工伤：资料归集
- 公积金：补缴计算
- 纸质回执电子化

**第三期（优化增效）**：
- 简历库智能管理
- 特种工智能管理
- 体系审核资料一键归集
- 试用期资料自动汇总
- 各类证明智能填充
- 费用单据智能整理

## 3. 功能需求

### 3.1 招聘管理

#### 3.1.1 人力需求发布

**功能描述**：

支持将招聘信息发布至前程无忧/中国人才热线等招聘平台。

**输入**：
- 岗位名称
- 岗位职责描述
- 任职要求（学历、经验、技能、年龄范围、证书要求等）
- 薪资范围
- 招聘人数
- 发布日期

**处理规则**：
1. 系统维护招聘平台账号信息和接口
2. 根据岗位模板自动生成招聘广告文案
3. 支持手动编辑招聘文案
4. 一键推送至已配置的招聘平台

**输出**：
- 招聘广告发布成功/失败状态
- 各平台发布链接

#### 3.1.2 多平台简历自动筛选与分类归档

**功能描述**：

AI 自动抓取前程无忧/中国人才热线等平台的投递简历，按岗位要求智能匹配打分，自动筛选并分类归档。

**输入**：
- 岗位要求条件（学历、经验、技能、年龄、证书等）
- 各招聘平台待筛选简历数据

**处理规则**：

1. **简历抓取**：
   - AI Agent 定时抓取各招聘平台的新简历投递数据
   - 支持手动触发抓取
   - 自动去重，避免重复简历
   - 简历去重规则：(1)一级去重（精确匹配）：同一候选人身份证号完全一致视为重复；(2)二级去重（高置信度匹配）：姓名+手机号完全一致且投递时间间隔不超过24小时视为重复；(3)三级去重（低置信度匹配）：姓名+手机号完全一致但投递时间间隔超过24小时，标记为疑似重复，推送人事人工确认；(4)去重优先级：同一岗位优先保留匹配评分较高的简历，跨岗位保留最早投递的简历。

2. **智能匹配评分**：
   - AI 解析岗位要求，建立匹配维度权重模型
   - 对每份简历进行多维度评分：
     - 学历匹配度（权重 20%）
     - 学历等级从高到低定义为：博士 > 硕士 > 研究生 > 本科 > 大专 > 中专 > 高中 > 初中 > 小学及以下，共9级。"低一级"指在此等级序列中低1级，如岗位要求本科，候选人学历为大专则视为低一级，得60%；候选人为中专则视为低两级，得0分。
     - 工作经验匹配度（权重 25%）
     - 经验匹配度说明：采用比例扣分模式与固定扣分模式并行的原因——学历是硬性门槛，比例扣分能体现学历差距的梯度影响；经验年限是线性积累指标，固定扣分便于HR理解和配置。两种模式在加权求和后均映射至0-100分区间，不影响总分可比性。
     - 技能匹配度（权重 20%）
     - 技能关键词命中率计算方式：(1)采用精确匹配模式，即简历中出现的技能关键词与岗位要求技能关键词完全一致（不区分大小写，忽略中英文空格差异）方视为命中；(2)命中率 = 简历命中的岗位技能关键词数量 / 岗位要求的技能关键词总数 × 100%；(3)技能库由系统管理员通过后台"技能管理"模块维护，支持增删改查，每条技能记录包含：技能名称、所属类别、别名（支持同义词匹配）。
     - 年龄匹配度（权重 10%）
     - 证书匹配度（权重 15%）
     - 综合匹配度（权重 10%，AI 语义分析）
   - 总分 0-100 分
   - 可配置合格分数线（默认 60 分）
   - AI 语义分析验收标准：AI 对简历文本与岗位描述进行语义相似度计算，采用余弦相似度或语义嵌入向量距离，输出 0-100 分的语义匹配评分，评分结果需可追溯（记录使用的模型版本和输入文本）
   - 验收条件定义：(1)同一份简历指：相同简历文本、相同模型版本号、同一自然日内进行的评分；(2)基准数据集：由人事专员从历史招聘记录中选取不少于50份已确认合格简历和50份已确认不合格简历组成；(3)测试方法：使用基准数据集运行AI语义匹配评分，统计合格简历的平均语义匹配得分和不合格简历的平均语义匹配得分，合格简历平均分应不低于70分，不合格简历平均分应不高于50分。

3. **自动分类**：
   - 合格简历（分数 >= 合格线）：自动下载并导入简历库
   - 不合格简历（分数 < 合格线）：自动标记为淘汰，保留记录
   - 待定简历（分数在 [合格线-10, 合格线+10] 闭区间内）：标记为待定，推送人事人工审核

4. **自动归档**：
   - 筛选完成后自动下载简历
   - 分类导入企业简历库
   - 同步打上岗位标签、匹配度标签
   - 建立简历电子档案

**输出**：
- 筛选报告（总投递数、合格数、淘汰数、待定数）
- 每份简历的匹配度评分和详细评分明细
- 简历自动归档至简历库
- 合格简历列表推送至人事

#### 3.1.3 面试试卷自动组卷与二维码生成

**功能描述**：

根据面试/转岗/试用期考核岗位，AI 从题库自动抽取试题组卷，一对一生成唯一考试二维码。

**输入**：
- 岗位名称或类型
- 考试类型（面试/转岗/试用期考核）
- 考生信息（姓名、身份证号、应聘岗位等）
- 组卷规则（题型比例、难度分布、题目数量等）

**处理规则**：

1. **题库管理**：
   - 系统维护岗位题库，支持按岗位、题型、难度分类
   - 支持批量导入题目
   - 支持题目增删改查

2. **自动组卷**：
   - AI 根据岗位和考试类型从题库自动抽取试题
   - 遵循组卷规则保证题目分布合理
   - 避免重复题目
   - 同一岗位同一场次考试中，任意两套试卷重复题目数量不超过较少套试卷题目总数的30%（按题目数量比例计算，向下取整）。例如：试卷A为30题、试卷B为50题，则重复题目不超过 floor(min(30,50) × 30%) = floor(9) = 9 题。
   - 支持不同考生生成不同试卷（题目随机抽取）

3. **二维码生成**：
   - 为每位考生生成唯一考试二维码
   - 二维码绑定考生信息与对应试卷
   - 二维码关联档案台账
   - 支持打印二维码或电子展示

**输出**：
- 生成的试卷内容
- 唯一二维码（可打印或电子展示）
- 考生-试卷-二维码关联记录

#### 3.1.4 面试答题自动评分

**功能描述**：

客观题由 AI 实时阅卷评分，生成评分明细，自动汇总考核成绩并推送结果。

**输入**：
- 考生二维码（扫码登录）
- 考生答题数据

**处理规则**：

1. **扫码登录**：
   - 面试人员扫描个人二维码进行身份验证
   - 系统验证身份后加载对应试卷

2. **答题过程**：
   - 考生在线作答
   - 系统记录答题时间
   - 支持客观题（单选、多选、判断）自动提交

3. **自动评分**：
   - 客观题由 AI 实时阅卷评分
   - 生成每道题的评分明细
   - 计算总分和各项得分

4. **结果处理**：
   - 自动汇总考核成绩
   - 成绩数据自动归档
   - 同步推送结果至部门主管及人事
   - 支持部门主管在线确认最终结果

**输出**：
- 考生个人成绩单
- 评分明细（每题得分）
- 考核结果自动推送通知
- 成绩归档记录

#### 3.1.5 简历库管理

**功能描述**：

管理企业简历库，支持简历导入、检索、分类、标签化管理。

**输入**：
- 简历文件（PDF/Word 等格式）
- 岗位标签
- 匹配度标签

**处理规则**：

1. **自动导入**：
   - 筛选后的合格简历自动导入简历库
   - 支持手动批量导入简历
   - AI 自动解析简历内容，提取关键字段

2. **智能管理**（第三期）：
   - AI 识别重复简历并标记
   - 简历信息更新提醒
   - 简历人才标签智能画像
   - 画像维度与输出格式定义：(1)画像维度包含：技能维度（技术栈、工具使用、语言能力）、经验维度（行业背景、工作年限、项目类型）、教育维度（院校层次、专业类别、学历等级）、潜力维度（学习能力评估、职业稳定性评分，由AI基于简历文本分析生成）；(2)输出格式为JSON结构，包含：候选人ID、各维度标签数组（标签名+置信度分数0-100%）、综合画像雷达图数据（6个维度各0-100分）。
   - 支持按岗位、技能、学历等条件检索

**输出**：
- 简历库列表
- 简历详情页面
- 检索结果
- 重复简历提醒

### 3.2 入职管理

#### 3.2.1 入职作业（第二期）

**功能描述**：

新员工扫码登录系统，完成实名认证、资料上传、协议签署等入职手续。

**输入**：
- 新员工二维码（唯一身份标识）
- 身份证正反面照片
- 学历证书照片
- 其他所需资料（如离职证明、体检报告等）

**处理规则**：

1. **扫码登录与实名认证**：
   - 新员工扫描入职二维码登录系统
   - 系统自动进行实名认证（比对身份证信息）
   - 法务要求的实名认证环节自动完成，包括：身份信息核验（对接公安身份认证接口或第三方实名认证服务）、人脸与身份证照片一致性比对、是否存在冒用身份检测

2. **资料上传**：
   - 员工自行上传人事相关资料
   - 支持附件上传功能
   - 必填资料清单：学历证、身份证、离职证明、体检报告等
   - 支持多种格式（PDF/JPG/PNG）

3. **证件智能识别**：
   - AIOCR 识别上传的证件信息
   - 自动提取关键字段（姓名、身份证号、学历、专业等）
   - 校验信息完整性
   - 信息不完整时自动提示补充
   - 证件影像按类型分类存入档案库

AIOCR识别验收标准：(1)测试集：使用不少于200张真实身份证、学历证书、离职证明扫描件（涵盖清晰、模糊、倾斜、光照不均等场景）；(2)测试方法：对测试集逐张进行AIOCR识别，统计关键字段（姓名、身份证号、学历、专业、发证日期等）的识别准确率；(3)验收标准：清晰扫描件关键字段准确率不低于99%，模糊/倾斜扫描件关键字段准确率不低于95%，整体平均准确率不低于98%。

   - 所有需签写的附加协议导入系统
   - 员工在线阅读协议内容

   - 系统记录签名时间、IP 等信息
   - 电子签名符合《中华人民共和国电子签名法》第十三条规定的可靠电子签名要求，具备签名人身份唯一性、签名可控性、篡改可发现性

**输出**：

   - 专项附加扣除字段来源与计算逻辑：(1)系统新增"员工专项附加扣除信息表"，包含字段：员工工号、扣除类型（子女教育/继续教育/大病医疗/住房贷款利息/住房租金/赡养老人/3岁以下婴幼儿照护）、月度扣除金额、起始月份、结束月份、证明材料路径；(2)员工在入职时或每年3-6月通过系统在线填报专项附加扣除信息，上传证明材料；(3)人事专员审核确认后生效；(4)薪资核算时，AI自动汇总该员工当月有效专项附加扣除金额并从应纳税所得额中扣除。

#### 4.2.1 数据安全

- 员工个人信息（身份证、人脸等）加密存储
- 薪资数据严格权限控制
- 数据传输采用 HTTPS 加密
- 数据库定期自动备份
- 敏感操作记录审计日志

#### 4.2.2 身份认证

- 所有用户登录需身份认证
- 面试官扫码验证登录
- 新员工实名认证
- 支持多因素认证（短信验证码）
- 短信验证码规则：(1)有效期：发送后5分钟内有效；(2)最大重试次数：单个手机号60分钟内最多发送3次验证码，超过3次则锁定该手机号60分钟；(3)错误尝试次数：连续5次输入错误验证码后锁定账号15分钟；(4)验证码长度：6位数字；(5)旧验证码在发送新验证码后立即失效。

#### 4.2.3 权限管理

- 基于角色的权限控制（RBAC）
- 不同角色访问不同功能模块
- 数据行级权限控制（如只能查看本部门员工数据）
- 操作权限分级管理

### 4.3 可用性需求

#### 4.3.1 系统可用性

- 薪资核算等关键操作支持校验和复核
- 灾难恢复指标：RTO（恢复时间目标）<= 4 小时，RPO（恢复点目标）<= 1 小时，即在系统故障后 4 小时内恢复服务，数据丢失不超过最近 1 小时

- 模块化设计，便于功能扩展
- 配置化规则管理（薪资规则、考勤规则等）

### 4.6 可扩展性需求

- 支持招聘平台接口扩展
- 支持打卡设备接口扩展
- 支持外部系统对接（如 ERP、财务系统）
- 支持自定义表单和流程
- 支持 AI 模型升级和替换

### 4.7 系统监控与告警需求

#### 4.7.1 服务健康检查

- 系统提供健康检查接口（/health），返回各微服务/模块运行状态
- 监控项包括：CPU 使用率、内存使用率、磁盘使用率、数据库连接池状态、消息队列堆积情况
- 阈值告警：CPU > 85% 持续 5 分钟、内存 > 90%、磁盘 > 85%、数据库连接池使用率 > 80%、消息队列积压超过 1000 条

#### 4.7.2 AI 模型异常检测

- 监控 AI 模型推理请求的响应时间、错误率
- 当 AI 模型错误率超过 5% 或响应时间超过 10 秒时触发告警
- 记录每次 AI 调用的模型版本、输入摘要、输出结果、耗时

#### 4.7.3 队列堆积告警

- 实时监控消息队列中待处理消息数量
- 当队列积压超过阈值（默认 500 条）时发出预警，超过 2000 条时发出严重告警
- 告警通知推送至系统管理员

### 4.8 AI 模型版本管理与回滚策略

- 系统维护 AI 模型版本 registry，记录每个模型的版本号、用途、上线时间、性能指标
- 支持多版本模型并存，新模型上线前可在测试环境验证
- 模型回滚策略：当新模型上线后出现异常（错误率 > 10% 或用户反馈异常），支持在 5 分钟内回滚至上一稳定版本
- 模型版本切换不影响正在处理的请求，新请求自动路由至目标版本

### 4.9 系统上线前数据验证与灰度发布

#### 4.9.1 数据验证

- 系统上线前执行数据验证：对比新旧系统数据一致性，验证范围包括员工档案完整率（要求 100%）、薪资数据核算结果比对（允许误差 0 元）、考勤记录条数核对（要求 100% 匹配）
- 数据验证报告由系统自动生成，包含验证通过项和差异项

#### 4.9.2 灰度发布

- 系统上线采用灰度发布策略：第一阶段对 10% 的用户/部门开放，观察 1 周；第二阶段扩大到 50%，观察 1 周；第三阶段全量上线
- 灰度期间支持一键回退至原系统
- 灰度发布期间实时监控用户反馈和系统指标

### 4.10 数据迁移需求

- 若从现有 HR 系统迁移数据，系统需提供数据迁移工具
- 支持的数据类型：员工档案、岗位信息、薪资历史、考勤记录、培训记录、绩效数据
- 迁移流程：（1）数据导出：从源系统导出结构化数据（CSV/Excel 格式）；（2）数据清洗：系统自动校验数据格式、去重、补全必填字段；（3）数据导入：批量导入至新系统；（4）数据验证：导入后执行数据一致性校验
- 迁移日志：记录每条数据的迁移状态（成功/失败/跳过），失败数据生成异常报告供人工处理
- 迁移回滚：迁移过程中支持中断和回滚，确保源系统数据不被破坏

## 附录 A：AI 原生系统架构设计要点

### A.1 AI Agent 编排

本系统采用多 AI Agent 协作架构：

1. **招聘 Agent**：负责简历抓取、筛选、匹配、评分全流程
2. **入职 Agent**：负责入职资料收集、证件识别、档案生成
3. **培训 Agent**：负责培训签到、考试评分、资料归集
4. **考勤 Agent**：负责考勤统计、异常识别
5. **薪资 Agent**：负责薪资核算、工资条生成
6. **绩效 Agent**：负责绩效考核数据收集和汇总
7. **外务 Agent**：负责工伤处理、公积金管理等外部事务

各 Agent 之间通过消息队列或事件总线通信（详见 5.2.5 Agent 间通信接口），实现端到端业务流程自动化。

### A.2 AI 能力集成

| AI 能力 | 应用场景 |
|---------|---------|
| NLP 语义理解 | 简历解析、岗位要求匹配、心得报告分析 |
| AIOCR | 证件识别、纸质回执识别 |
| 计算机视觉 | 人脸采集与比对、签名验证 |
| 智能评分 | 客观题自动阅卷 |
| 智能组卷 | 基于题库的自动试题抽取 |
| 视频生成 | 教材转视频 |
| 智能提醒 | 证书到期提醒、复训提醒 |
| 数据汇总分析 | 绩效汇总、培训评估报告生成 |

### A.3 人机协作模式

| 场景 | AI 处理 | 人工处理 |
|------|---------|---------|
| 简历筛选 | 自动匹配评分、分类归档 | 待定简历人工确认 |
| 面试评分 | 客观题自动评分 | 主观题人工评分 |
| 入职办理 | 证件识别、档案生成 | 异常处理 |
| 薪资核算 | 自动计算 | 异常薪资复核 |
| 离职申请 | 表单自动生成 | 主管审批 |
| 工伤理赔 | 资料归集 | 最终确认提交 |
